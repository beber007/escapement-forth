The rules

    
    
      
  • hard real time · EDF
    • 
      
  • 4 tasks · 1, 10, 100, 1000 ms
    • 
      
  • the Pico's Forth and kernel · a Raspberry Pi Pico
    • 
      
  • in your browser · nothing is sent
    • 
    

    
    
      
  1. Four tasks, sixteen slotsThe kernel has four tasks, with periods of 1, 10, 100 and 1000 ms.
        Each has four slots. You attach words to them from the console: ' blink 100 every.
    2. 
      
  2. On trial firstA new word is on trial. It runs every period, and each run is timed. Its budget is a tenth of its period. If it goes over, it gets cut off.
    3. 
      
  3. Promoted or refusedAfter ten runs, none over budget, promote reserves it a share of the processor. That time is guaranteed. All promoted words must fit in 70% of the processor. If they don't, the word is refused. Words on trial count too: all the budgets must fit in 95%. So nine words on trial at most.
    4. 
      
  4. Earliest deadline firstThe kernel always runs the task with the earliest deadline (EDF).
        The 1 ms task interrupts the 1 s task. The console comes after all of them.

This web page and the board

    
    
      
  • Forth and the kernel are the code of the real board, a Raspberry Pi Pico, compiled as is: the console and
        the slots (src/), Escapement's real-time kernel, which schedules by EDF (EscapementHard.c) and
        the Pico's four tasks, one per period. Only the layer below changes (web/platform_web.c,
        web/kernel/).
    • 
      
  • Here, the console is the kernel's background task. The slots interrupt it, and each
        other, where Forth reads the clock: every sixteen words. On the board, the console has its own core and never delays a slot.
    • 
      
  • The kernel's clock follows the browser's. The browser only runs the web page every few
        milliseconds, less often in a hidden tab. The kernel then catches up, one run after another.
        Each is on time for the kernel but late in real time. Beyond 200 ms, the rest is dropped.
        The browser sometimes pauses in the middle of a run, for garbage collection for example.
        A pause of more than about half a millisecond is counted neither by the clock nor in the measurements. The board has no
        such pauses.
    • 
      
  • On a real Pico, the times shown are the Pico's. Here, they are your browser's. They are read to a tenth of a
        millisecond, or to a millisecond depending on the browser. Some browsers round further to
        protect your privacy. The web page then says so. A very short word can show 0, and an
        empty task has no width on the timeline. This web page says nothing about what the kernel
        costs on a real chip, or about its energy use.
    • 
      
  • A typed line is stopped after 10 s, like Ctrl-C on the board. The words you define vanish with the web page: save has no flash to write to.
